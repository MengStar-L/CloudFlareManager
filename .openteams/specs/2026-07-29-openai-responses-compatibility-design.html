OpenAI Responses 全兼容层

CF-R2Manager design note · 2026-07-29 · 待用户书面确认

为 POST /v1/responses 增加稳定的 OpenAI Responses ↔ Workers AI Chat Completions 适配层，覆盖 Sub2API 实际请求、流式与非流式文本、图片输入、函数调用、工具结果、JSON Schema、 reasoning 和 usage。兼容范围以 Cloudflare Workers AI 能力为边界；无法实现的 OpenAI 托管功能明确返回 400 unsupported_feature，不伪造成功结果。

问题与成功标准

当前管理页 Playground 固定调用 /v1/chat/completions，请求中有 messages，因此可用； 外部 /v1/responses 只改写上游 URL，仍把 Responses 的 input 原样发给模型。 大量 Workers AI 模型只校验 prompt 或 messages，所以返回用户看到的 invalid_prompt。

完成后必须满足以下可验证结果：

  • Sub2API 的真实测试载荷可在任一兼容的 Workers AI 文本生成模型上收到 response.output_text.delta 和最终 response.completed。
  • 同一模型通过管理页 Chat Completions 与外部 Responses 调用时，核心文本、工具调用和错误语义一致。
  • 现有 /v1/chat/completions、/v1/embeddings、/v1/run/* 不改变协议或响应。
  • 不支持的模型任务或 Responses 功能在请求发往 Cloudflare 前得到明确、标准的 OpenAI 错误。

成熟实现调研与选型

方案证据结论
直接依赖 CLIProxyAPI 的 sdk/translator/builtin MIT；约 45k stars；v7.2.104 已公开 Responses ↔ Chat 转换和 30 个相关测试。 不采用直接依赖。其 built-in 会注册全部 Claude、Gemini、Codex 等转换，并带入 Redis、配置和插件代码；实测加载 83 个非标准库包，超出本项目需要。
带归属引入 CLIProxyAPI 的聚焦转换核心 固定参考 tag v7.2.104、commit c9417c8ae9b16fabc0386ca35d36f13bf8b1d678；已有交错工具调用、迟到 usage、SSE 完成时序和图片输入测试。 采用。只移植 OpenAI Responses ↔ OpenAI Chat Completions 的请求、流式响应和非流式响应逻辑；保留 MIT 版权，记录本项目修改。
openai-responses-adapter 或从零实现 前者为 Apache-2.0、用途聚焦，但规模小、核心 API 位于 internal，多模态和完整 SSE 覆盖不足。 仅作为行为对照，不作为主体；从零实现会重复成熟项目已经解决的工具状态和事件排序问题。

选型结论：转换状态机来自成熟 MIT 项目，Cloudflare 专属的字段白名单、能力拒绝和参数补全由本项目维护。 NOTICE 增加 CLIProxyAPI 来源、版本和许可证；移植文件保留上游版权头与修改说明，不复制 LGPL 的 Sub2API 源码。

架构与数据流

1. 验证解析 JSON、检查 model/input、拒绝不可实现功能
2. 转换请求Responses input/tools/text 转为 Chat messages/tools/response_format
3. Workers AI统一调用 /ai/v1/chat/completions，保留账户选择与重试
4. 转换响应Chat JSON 或 SSE 转为 Responses 对象与类型化事件
5. 记录沿用请求日志、账户错误、延迟与估算 neuron 统计

新增聚焦包 internal/modules/ai/responsescompat，只负责协议转换，不知道账户、数据库或 HTTP 鉴权。 Gateway.Forward 在路径为 /v1/responses 时调用它；其他路径继续走现有透传逻辑。 Responses 请求始终转换到 Chat Completions，避免依赖 Cloudflare 原生 Responses 在不同模型上的不一致支持。

转换接口返回结构化结果：上游路径、请求体、是否流式，以及流式转换器或非流式转换函数。 HTTP 层仍负责 16 MiB 请求上限、账户重试、Header、Flush、审计和错误状态，协议包不直接写网络。

流式响应契约

SSE 解析器按事件边界处理，不假定一次网络读取就是一行或一个 JSON。支持 CRLF/LF、data: 后有无空格、 注释行、分片 JSON 和多个事件同批到达；单事件设置合理上限，防止无界内存增长。每个输出事件同时写 event: <type> 和 data: <json>，并立即 Flush。

文本流的完整顺序为：

response.created
response.in_progress
response.output_item.added
response.content_part.added
response.output_text.delta        (0..N)
response.output_text.done
response.content_part.done
response.output_item.done
response.completed

函数调用另外产生 response.output_item.added、 response.function_call_arguments.delta、response.function_call_arguments.done 和 response.output_item.done。状态按 choice index + tool index/call ID 隔离，允许多个工具交错到达； sequence_number 严格递增，output_index 稳定。[DONE] 只结束上游 Chat 流， 对外必须先发一次且仅一次 response.completed，不把 [DONE] 当作 Responses 终止事件。

若上游提供 reasoning_content，转换为 reasoning summary 事件/输出项；若未提供则不伪造推理内容。 若流式 usage 缺失，完成事件省略 usage；日志中的字节估算不冒充模型 token usage。

非流式响应

Chat Completions 的 choices[].message 转为单个标准 object: "response"：文本生成 message/output_text，工具调用生成 function_call；响应包含稳定 ID、created_at、model、status、output、 error/incomplete_details 和可用的 usage。prompt/completion/total tokens 分别映射为 input/output/total tokens，缓存和 reasoning 明细只在上游真实返回时出现。

明确不支持的功能

以下能力不是 Workers AI Chat Completions 可等价提供的功能，统一返回：

{
  "error": {
    "message": "...",
    "type": "unsupported_feature",
    "code": "unsupported_feature",
    "param": "background"
  }
}

background previous_response_id / conversation prompt templates web_search file_search computer use code interpreter hosted MCP input_file / file_id audio output prediction

store: false 和缺省 store 可用于无状态生成；store: true 返回 unsupported，因为本服务不提供 Responses 检索/删除接口。调用方需要多轮对话时必须在下一次 input 中提交完整历史。非文本生成任务应使用现有 /v1/embeddings 或 /v1/run/<model>，不能通过 Responses 伪装成文本模型。

错误、重试与安全

  • JSON 语法、必填字段、content/tool 结构错误：本地 400 invalid_request_error，包含准确 param。
  • 明确越界功能：本地 400 unsupported_feature，不请求 Cloudflare、不计入推理使用量。
  • 模型不支持图片、工具、JSON 或 reasoning：保留 Cloudflare HTTP 状态和可读 message，并规范化为 OpenAI error 对象。
  • 现有 429/5xx 跨账户重试保留；任何响应正文写给客户端后不再重试，防止两个流拼接。
  • 请求体继续限制 16 MiB；SSE 单事件设置上限；客户端取消会取消上游请求。
  • 日志记录模型、状态、耗时和错误类别，不记录 instructions、messages、图片 data URL 或工具参数正文。

范围边界

本次只修复并完善 POST /v1/responses 的无状态推理兼容层与相关错误规范化；不新增数据库表、 Response 对象存储、后台任务、检索端点、WebSocket Responses、模型能力缓存或管理页新功能。 Cloudflare 自身的 AI Gateway ID 转发行为、账户路由和已有 API key 体系保持不变。
