WebDAV 条件请求与强 ETag 修复

CF-R2Manager v0.5.2 设计基线 · 2026-08-29
结论：当前问题位于 CF-R2Manager 的 WebDAV 层。HTTP GET 已返回带引号的强 ETag， 但 PROPFIND 输出未加引号，修改方法也没有执行客户端条件，因此 GameSync 的条件写入能力探测失败。

目标与验收

  • GET、HEAD、PUT 和 PROPFIND 使用同一强 ETag 表示。
  • 支持 RFC 9110 条件头以及 RFC 4918 DAV If 条件和锁令牌。
  • 条件失败返回 412，语法错误返回 400，且失败请求没有写意图、配额或 R2 副作用。
  • GameSync 的 create-only、stale write 和 current write 探测全部通过。
  • 外部 S3 API、数据库结构和现有无条件调用保持兼容。

架构

层职责
WebDAV 协议层严格解析条件头、统一 ETag 格式、执行 HTTP 优先级和状态码映射，并解析完整 DAV If 布尔表达式。
SQLite 索引层在创建写意图的同一事务内检查存在性、ETag 和修改时间。它是逻辑命名空间的 CAS 权威。
R2 后端层在 PutObject 或 CompleteMultipartUpload 发布点增加物理条件，防止索引校验后的并发覆盖。

协议行为

  • If-Match 使用强比较；If-None-Match 使用弱比较；日期按 HTTP 秒精度比较。
  • 无效或重复的日期条件按 RFC 9110 忽略；日期型 If-Range 因秒精度不足而保守回退为完整响应。
  • GET/HEAD 的缓存条件失败返回 304；修改方法的条件失败返回 412；失效的 If-Range 忽略 Range 并返回完整响应。
  • DAV tagged URI 必须同源且可映射到当前凭据命名空间，非法或无法映射的条件返回 400。
  • PUT、MKCOL、DELETE、COPY 和 MOVE 对每个受影响键重新校验条件。Overwrite: F 是原子目标不存在条件。
  • 集合 COPY/MOVE 维持逐项操作，部分失败以 207 Multi-Status 表达，不提供整树回滚。
  • 只保留现有 exclusive write 锁。DAV 条件失败优先于缺失锁令牌；后者返回 423。
  • 为兼容 R2 对象键和现有 GameSync 客户端，PUT/MKCOL 继续允许缺失的中间集合，并将其视为虚拟集合；文件祖先冲突仍被拒绝。这是有意保留的 RFC 4918 409 行为差异。

一致性与错误

  • 单键 CAS 由 SQLite 写意图事务保证；并发中的活动写意图保持返回 423，重试时再根据新 ETag 返回 412。
  • 新物理键使用 If-None-Match: *，同桶覆盖使用已索引的物理 ETag；跨桶写入不复用旧桶 ETag。
  • 逻辑条件已通过后出现的 R2 412/409 视为物理状态冲突并对外返回 409；R2 429 保持独立。
  • 直接绕过本程序修改底层 R2 所造成的既有索引漂移不在本次修复范围内。

验证与发布

测试覆盖解析器、事务零副作用、并发写入、AWS SDK 请求、全部 WebDAV 方法、锁、凭据隔离及 GameSync 探测序列。 合并前运行 Go race/vet/test、前端 lint/build 和生产构建；发布 v0.5.2 后在生产环境使用一次性对象执行探测并清理。 本次无数据库迁移，必要时可直接回退到 v0.5.1。
