File Context Menu Position

CF-R2Manager design note, 2026-07-27

Render the file context menu at the pointer's viewport position, while keeping the complete menu inside the viewport near the right and bottom edges.

Observed Behavior

FilesPage records right-click coordinates with MouseEvent.clientX and clientY. FileContextMenu then uses those viewport coordinates with position: fixed. However, the menu is currently rendered inside the Motion-based PageTransition, whose computed transform and filter establish a containing block for fixed descendants. The browser therefore interprets viewport coordinates relative to the animated page container and adds a visible horizontal and vertical offset.

Options Considered

ApproachBenefitTrade-off
Portal the menu to document.bodyKeeps viewport coordinates and fixed positioning semantically aligned.Requires one React portal boundary.
Subtract the page container rectangleSmall local arithmetic change.Couples positioning to the current shell, padding, animation, and responsive layout.
Lift menu rendering above PageTransitionAvoids the transformed ancestor.Introduces cross-page state and prop plumbing for a file-page-only concern.

Selected Design

FileContextMenu will use createPortal to render its existing menu element directly under document.body. Its API and callers remain unchanged. Right-click continues to pass pointer viewport coordinates; the ellipsis button continues to pass coordinates derived from getBoundingClientRect.

A layout effect will read the menu's untransformed offsetWidth and offsetHeight before paint. The final position is clamped to the viewport with an 8-pixel margin. Away from an edge, the menu's top-left corner matches the requested coordinates. Near the right or bottom edge, only the overflowing axis moves inward.

Interaction And Accessibility

  • The first menu item still receives focus when the menu opens.
  • Clicking outside, pressing Escape, or scrolling still closes the menu.
  • Menu roles, labels, actions, styling, animation, and keyboard focus appearance do not change.
  • Files and directories use the same positioning behavior; WebDAV mount rows remain excluded.

Error And Lifecycle Handling

The portal is created only in the browser while an entry menu is open, so document.body is available. Event listeners remain owned by FileContextMenu and are removed on unmount. The positioning calculation uses the actual rendered dimensions instead of duplicating menu height assumptions for files and directories.

Verification

  • Right-click a file and a directory in the center of the table; the menu opens at the pointer with no shell-offset displacement.
  • Right-click near the right and bottom viewport edges; the menu remains fully visible with an 8-pixel margin.
  • Open the same menu from the ellipsis button; it remains anchored below and beside that button.
  • Verify outside click, Escape, scroll dismissal, focus, and every menu command still work.
  • Run npm run build and inspect desktop and mobile viewports without console errors or overlap.

Scope

The product change is limited to FileContextMenu and any focused positioning test or browser fixture needed for verification. It does not change file APIs, menu actions, page routing, global motion behavior, or other popovers.
