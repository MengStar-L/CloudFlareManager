远端 R2 存储桶删除与“一键清空并删除”

CF-R2Manager v0.5.2 设计基线 · 2026-08-30 · 已经用户逐节确认
设计结论：新增两个含义明确的远端操作：“仅删除空桶”和“清空所有对象并永久删除”。 两者统一通过可续跑后台任务执行。阵列内桶在执行期间进入持久删除状态；只有 Cloudflare 远端桶确认消失后， 才事务性清理本地索引和阵列登记。任何不确定或部分失败都保留恢复依据，绝不先删本地记录。

1. 背景、目标与边界

当前“物理桶”页面可以创建 Cloudflare R2 桶并纳入阵列，但垃圾桶图标实际只执行本地“移出阵列”。 产品没有调用 Cloudflare 删除桶接口，非空桶或凭据删除失败时还会直接暴露英文信息，用户无法判断需要先清空对象。

目标在同一页面安全删除远端空桶，并提供后台“一键清空并删除桶”。
一致性阵列内桶成功后自动移除本地登记；失败保留桶、索引、任务和中文原因。
可恢复支持服务重启、Cloudflare 超时、限流和远端已删但本地未收尾等场景。
可理解区分“移出阵列”“删除空桶”“清空并永久删除”，不再混用同一语义。
明确不做：不自动解除 Cloudflare Bucket Lock/保留策略，不清理自定义域名或 DNS，不承诺恢复已经删除的对象， 不把分析统计中的对象数当作删除依据，不使用 Cloudflare Dashboard 的非公开 Empty Bucket 实现， 也不提供已产生远端删除副作用后的任务取消或数据恢复。本期远端删除只支持 default jurisdiction； EU、US、FedRAMP 等桶继续显示，但删除入口禁用并说明版本限制。

2. 已选方案与替代方案

方案行为结论
混合清空优先用 R2 S3 API 批量删除对象并中止未完成分片；缺少可用 S3 凭据时回退 Cloudflare REST 逐个删除；最后用 REST 删除桶。采用兼顾大桶效率、现有凭据复用和未纳管桶可用性。
仅 RESTREST 分页列对象并逐个删除。实现较少，但每个对象一次请求，容易受 API 限流影响，不作为首选。
生命周期规则创建全桶过期规则并等待异步清理。通常需要等待，且规则期间的新对象也会被删除，不符合即时“一键”体验。

3. 架构与职责边界

Cloudflare REST 客户端获取桶身份、列/删对象、删除桶；保留 jurisdiction；把 HTTP 状态和 Cloudflare code 解析成结构化错误。非 default 桶在任何破坏请求前失败关闭。账号 API Token；不接触本地索引。

存储页面呈现不同删除语义、危险确认、任务阶段、已删计数和中文失败原因。远端桶列表与通用 jobs API。

4. API、任务载荷与持久状态

创建删除任务

POST /api/v1/r2/remote-buckets/{bucket_name}/deletions

请求体为 { account_id, jurisdiction, mode, confirmation_name, admin_password }；mode 只能是 empty_only 或 empty_and_delete。成功返回 202 Accepted 和标准 job。 empty_and_delete 模式必须提供与路径桶名完全一致的 confirmation_name，并由后端校验； empty_only 可省略该字段。jurisdiction 必须为 default；其他值返回 unsupported_jurisdiction。管理员密码只用于本次验证，禁止写入 job、日志或审计。

服务器在入队前从 Cloudflare 重新读取桶，而不是信任浏览器提交的身份。任务载荷保存：

  • 本地账号 ID、Cloudflare 账号 ID、桶名、固定为 default 的 jurisdiction、规范化后的远端创建时间；
  • 提交时的本地物理桶 ID（可空）、模式、当前阶段、已删对象数、已终止分片数；
  • remote_mutated，表示是否已经删除对象或中止 multipart 等不可逆远端副作用；以及任务开始前的 lifecycle state，用于决定无副作用失败能否恢复。

阵列内桶状态

为 r2_physical_buckets 增加 lifecycle_state（ active、deleting、delete_failed）和可空的 deletion_job_id。 原有 writable 继续表达管理员配置；生命周期状态独立表达删除隔离，避免失败恢复时错误地把原本只读的桶改成可写。

deleting/delete_failed 桶仍保留本地对象索引作为恢复依据，但逻辑 S3/WebDAV 的 GET/HEAD 对映射到该桶的对象返回稳定的暂时不可用错误， 不把清空过程中出现的物理 404 暴露成普通“文件不存在”。逻辑列表可继续显示这些索引项，并标明桶正在删除或删除失败。

jobs 增加 resource_key 与 error_code。删除任务的 resource key 是规范化的 account_id/default/bucket_name；pending/running 状态使用部分唯一索引原子去重，而不是先查后插。 jobs Store 增加 FailPermanent，让身份变化、非空和权限等确定错误立即结束。

阵列内桶同时用 deletion_job_id 绑定当前任务。失败后的“重试”总是创建带 parent_job_id 的新任务， 重新要求密码与危险确认；如果桶原先为 delete_failed，新任务从父任务继承 expected identity 和 remote_mutated，不得把它当作全新桶重新取基线。

5. 删除状态机与数据流

验证桶身份
持久隔离
清空对象
终止分片
删除远端桶
本地事务收尾
  1. 验证身份：按账号、default jurisdiction、桶名和规范化创建时间验证当前远端桶；创建时间缺失、无法解析或发生变化均失败关闭。 每轮对象/分片破坏操作前，以及调用 Delete Bucket 前一刻，都重新 GET 并比较身份。若提交时远端已经不存在，仅当存在同账号、同桶名的本地登记时 才允许创建“本地残留收尾”任务；执行时再次确认远端仍不存在，若同名桶出现则停止。
  2. 持久隔离：任务开始时先在数据库中把阵列内桶从 active 原子切换为 deleting，此谓词本身就是重启后的安全边界。 所有新 PUT、覆盖（即使新物理目标是其他桶）、DELETE、multipart 创建/新分片、目标对象读取和维护入口都必须在各自事务内直接要求 lifecycle_state = 'active'；维护锁只提供运行期互斥，不承担持久隔离。已经创建的普通写意图可以完成或由恢复逻辑收敛， 已有 multipart 则由删除任务协调中止并释放本地预留。活动意图归零后，任务再取得维护锁进入清空。
  3. 清空：empty_only 跳过清空。empty_and_delete 优先从第一页反复执行 S3 列举与批量删除，避免删除过程中继续使用失效游标；随后列举并终止所有未完成 multipart。缺少可用 S3 凭据时，REST 按游标列举并以受限并发逐个删除普通对象； REST 无法列举或终止 multipart，如果最终删除仍受未完成分片阻止，任务返回 s3_credentials_required，而不是假装已经清空。
  4. 删除远端桶：再次确认对象和可见 multipart 均为空，紧接着重新 GET 对比身份，再调用 Cloudflare DELETE。 若外部客户端在间隙写入并触发 BucketNotEmpty，执行有限轮重新清空；持续出现新对象则以“仍有外部写入”失败。 DELETE 超时后不得盲目重发：先 GET；不存在则进入本地收尾，身份相同才可再次尝试，身份改变则永久停止。
  5. 本地收尾：只有远端 DELETE 成功，或经过身份校验确认该桶已经不存在，才执行一个 SQLite 事务，删除目标桶对应的 objects、multipart/parts、write intents、physical cleanups、scan findings、placement rules、maintenance lock 和物理桶行。 本期不主动删除仍有效的 WebDAV 锁：它们最长一小时自动过期，清理过程只移除已经过期的锁，避免误删仍覆盖其他物理桶对象的目录深度锁。 事务失败时全部本地桶引用一起保留。
  6. 完成：任务置为 succeeded，审计记录远端与本地均已完成，页面刷新后桶从列表消失。

任务每个阶段都可幂等重入。若进程在“远端已删、本地未清”之间退出，重试会把经身份校验的远端 Not Found 当作远端成功，继续本地收尾。 Cloudflare Delete Bucket 不支持 generation/ETag 条件，因此无法消除外部特权客户端在最后一次 GET 与 DELETE 之间删除旧桶并重建同名桶的 TOCTOU 窗口； 本设计通过缺失身份即拒绝、逐批复验和不盲目重试把窗口降到最小，并要求任务活动期间不得在 Cloudflare 外部重建同名桶。

6. 失败恢复与一致性规则

失败点远端副作用本地处理后续
密码、参数、权限预检失败无不入队；若任务原本从 active 开始且尚无副作用，可恢复 active。此前已经是 delete_failed 的桶继续保持隔离；原 writable 始终保留。修正后重新提交。
仅删除空桶收到 BucketNotEmpty无任务从 active 开始时恢复 active；从 delete_failed 重试时继续保持隔离。全部索引和登记均保留。手动清空或选择一键清空。
清空中网络/限流失败可能已有对象删除保持 deleting 并自动重试；达到上限后为 delete_failed，继续阻止写入。从第一页重列并安全续跑。
持续外部写入已部分清空保留本地索引与登记，置 delete_failed。停止外部客户端后重试。
远端成功、本地事务失败桶已不存在保留本地登记和 job，状态为 deleting/delete_failed。重试跳过远端并完成本地事务。
检测到同名新桶或身份不可验证检测后不再产生副作用保留本地现场并永久失败。管理员先清理旧登记并重新审视新桶。

为避免无意义重试，jobs runner 增加可识别的永久错误和 FailPermanent：非空空桶、身份变化/不可验证、明确权限不足、 unsupported jurisdiction 和 Bucket Lock 直接结束；网络、429、5xx 和结果不确定错误使用现有 lease/指数退避重试。 最终错误文本必须是中文，结构化 code 写入 jobs.error_code。

7. 页面交互

  • 阵列内桶使用 Unlink 图标表示“移出阵列（保留 Cloudflare 桶与对象）”；红色 Trash 才表示“永久删除 Cloudflare 存储桶”。
  • 永久删除打开独立对话框。默认选择“仅删除空桶”；第二项为红色的“清空所有对象并永久删除”。两种模式都要求管理员密码，清空模式还必须输入完整桶名； 后端再次校验桶名，不能绕过浏览器确认。
  • 分析统计对象数只作参考，不据此禁用按钮或断言空桶。Cloudflare DELETE 是空桶的最终判定。
  • 列表按账号、jurisdiction 和桶名区分同名桶；非 default 桶显示区域标签并禁用删除，提示当前版本不支持该区域。
  • 提交后从 jobs API 恢复任务状态，即使刷新页面也显示等待、隔离、清空对象、终止分片、删除桶、收尾、失败及已删计数。
  • 失败桶保留在列表中并提供“重试删除”。remote_missing 且存在本地残留时显示“清理本地残留”，走同一幂等收尾逻辑。
  • 现有“移出阵列”若仍被对象或任务引用，返回中文说明，不再显示笼统的 physical bucket is still referenced。

前端 APIError 增加 code 字段；对话框、Toast、桶行和活动页面均展示后端中文 message。 未分类错误的兜底信息同时提示检查“对象/分片是否清空、权限和网络”，但不得把 403、429 或网络错误伪装成非空。

9. 测试与验收

  • 远端适配器：REST/S3 请求方法、路径、鉴权、default jurisdiction、非 default 拒绝、对象键编码、分页、批量响应逐项错误、multipart 中止，以及 403/404/409/429/5xx/非 JSON 响应。
  • 后台任务：resource_key 并发提交唯一性、父子重试继承、阶段与计数持久化、lease 续期、重启续跑、远端 404 幂等收尾、 创建时间缺失/变化失败关闭、DELETE 超时后先复验、永久与可重试错误。
  • 并发一致性：切换 deleting 后不再产生新意图，已有普通意图可收敛、已有 multipart 可协调中止；活动意图清零前不能取得维护锁。 隔离后读取、PUT、跨桶覆盖、DELETE、multipart 和维护操作均得到确定响应；持续外部写入最终安全失败。
  • 数据库：远端失败时全部本地记录保留；远端成功后依赖项完整清理；本地事务注入失败后可重试；原始 writable 配置不被错误修改。
  • HTTP：会话、CSRF、管理员密码、服务端精确桶名确认、模式/桶名验证、中文稳定错误码、审计无密钥。
  • 前端：执行 lint、生产构建和本地浏览器烟测，验证 Unlink/Trash 语义、两种模式、桶名确认、刷新后进度恢复和失败重试。
验收标准：default 区域空桶能删除，其他 jurisdiction 明确拒绝；非空桶在 empty-only 模式得到中文提示； 一键模式总能清理可访问的普通对象，并在配置可用 S3 凭据时清理未完成分片；阵列内桶仅在远端成功后自动移出； 任一失败或服务重启都不丢失恢复现场；检测到桶身份缺失或变化后不再继续破坏操作；任何输出不泄露 Token、密码或 S3 Secret。

自动化测试使用模拟 Cloudflare REST 与 S3 服务，不触碰现有真实桶。部署后的真实验证只使用专门创建、可安全销毁的临时测试桶。

10. 迁移、启动恢复与回滚

  • 数据库迁移为 r2_physical_buckets 增加生命周期字段（默认 active），并为 jobs 增加 resource_key/error_code 与活动资源部分唯一索引。
  • 所有协议和维护入口直接把 lifecycle state 作为数据库准入谓词，所以启动时清理进程级维护锁不会产生写入窗口；后台 job 随后重新取得运行期维护锁并续跑。
  • 发布后先用专门临时桶验证 empty-only，再用另一个带普通对象和测试 multipart 的临时桶验证一键模式；不得使用现有业务桶。
  • 旧版本不认识 lifecycle state。只有数据库中不存在 deleting/delete_failed 桶时才能回退到旧二进制；存在任何此类桶时必须先用新版本完成或安全处置，避免旧版本重新向残缺桶写入。

11. 官方行为依据

  • Cloudflare：Delete buckets — 桶必须完全为空；Bucket Lock 会阻止清空。
  • Cloudflare API：Delete Bucket — API Token 权限与 jurisdiction 请求头。
  • Cloudflare API：Get Bucket — 破坏操作前重新读取桶身份。
  • Cloudflare API：List Objects — REST 对象分页与每页上限。
  • Cloudflare：S3 API compatibility — ListObjectsV2、DeleteObjects 与 multipart 操作支持情况。
